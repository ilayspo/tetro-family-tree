# עץ המשפחה של משפחת טטרו

פרויקט עצמאי למשפחת טטרו. התצוגה הציבורית והניהול בעברית. המקור העיצובי הוא אתר משפחת רובין, אך המאגר הזה אינו מכיל את נתוני רובין, את ה־seed שלהם או מפתחות Supabase.

## התחלה

- יוצרים פרויקט **Neon חדש ונפרד**, באזור שתומך ב־Managed Auth וב־Object Storage. בודקים את מכסות החשבון ואת זמינות האחסון בפרויקט לפני ההקמה.
- מפעילים Managed Better Auth עם כניסת email/password ואימות כתובת דוא״ל, ויוצרים bucket פרטי בשם `tetro-photos`. אין לאפשר הרשמה חופשית לאתר הניהול.
- מחילים `db/001_schema.sql` על ענף ברירת המחדל בפרויקט החדש בלבד. הסקריפט יוצר בדיוק שני אנשים, ציפורה ומיכאל טטרואשוילי, ואת יחידת הנישואים שלהם. הוא אינו מניח אם הקשר נוכחי.
- יוצרים חשבון Auth מאומת למנהל. את `user.id` שלו מוסיפים ל־`tree_admins` באמצעות חיבור מסד מנהלי חד פעמי: `insert into tree_admins(user_id) values ('<verified-user-id>');`. אין להכניס סיסמה או user ID לקוד הציבורי.
- מעתיקים את `.env.example` ל־`.env.local` וממלאים ערכים מן הפרויקט החדש בלבד. מריצים `npm install`, `npm run dev`. ב־Vercel מגדירים את אותם משתני סביבה כ־Production secrets, מייבאים את המאגר החדש ומפעילים deployment אוטומטי מענף `main`.

## גבולות הגישה

`/api/tree` מחזיר רק אנשים גלויים וקשרים בין אנשים גלויים, עם `Cache-Control: no-store`. העמוד אינו מחזיק snapshot ישן. `/api/admin` וכל כתיבה לתמונות דורשים session של Neon Auth וגם רשומה ב־`tree_admins` בצד השרת. החיבור למסד ופרטי S3 נשארים במשתני סביבה בשרת; bucket התמונות פרטי, ו־`/api/photo/:id` משרת תמונה רק כשהפרופיל גלוי. אין להפעיל Data API ציבורי על הטבלאות הללו. בהתקנה עם Data API יש להגדיר הרשאות RLS בהתאם, או להשאיר אותו כבוי.

המודל מקצה לכל ילד יחידת הורים אחת בלבד (אחד או שניים). שינוי הורה מתבצע בפעולת שיוך מחדש; בדיקות שרת מונעות הורות עצמית, מעגלים, כפילות פרופיל זהה וקשר ילד סותר. פעולת יצירת פרופיל והקישור הראשוני נמצאים באותה עסקת מסד. רשומות מוסתרות וקשריהן אינם יוצאים ל־API הציבורי. תאריך חלקי נשמר כמחרוזת בלי להשלים חודש או יום.

## שימוש בניהול

נכנסים ל־`/admin.html`, לוחצים „הוספת אדם”, ממלאים שם ובוחרים „ילד/ה של”. בוחרים את הזוג „ציפורה טטרואשוילי + מיכאל טטרואשוילי” בשדה הזוג, בודקים את סיכום הקשר, בוחרים אם להציג את האדם באתר ושומרים. אפשר להשאיר שם רוסי ותאריכים ריקים. תמונה אפשר להעלות אחרי שמירת הפרופיל. תיקון הורים נעשה באזור „קשרים ועריכה” בפרופיל הילד.

## בדיקת התקנה

נכנסים כמנהל, יוצרים אדם זמני וקשר עם זוג השורש, מרעננים את `/tree.html`, עורכים את הפרופיל ומצב היחידה, ובודקים העלאת תמונה והסתרה. מוחקים את פרופיל הבדיקה בכפתור „מחיקת פרופיל” ומוודאים שגם התמונה הוסרה. בדקו שה־API הציבורי אינו מחזיר אדם מוסתר, ושה־API המנהלי מחזיר 401 ללא session ו־403 לחשבון ללא הרשאה.

לפריסה פעילה נדרשת השלמת הפרויקט, חשבון המנהל, bucket, הגדרת סודות Vercel וחיבור GitHub. ללא החיבורים הללו העמוד מציג הודעת אי־זמינות במקום מידע מומצא.
