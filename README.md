# עץ המשפחה של משפחת טטרו

פרויקט עצמאי למשפחת טטרו. התצוגה הציבורית והניהול בעברית. המקור העיצובי הוא אתר משפחת רובין, אך המאגר הזה אינו מכיל את נתוני רובין, את ה־seed שלהם או מפתחות Supabase.

## התחלה

- פרויקט Neon הנפרד הוא `wispy-dream-84344395`, ענף הייצור `br-billowing-surf-b1tl8rri` באזור `aws-eu-central-1`. גבול נפח המסד המדווח בפרויקט הוא 512MiB.
- Managed Better Auth פעיל, וה־bucket הפרטי `tetro-photos` נוצר. חשבון המנהל `ilayspo@gmail.com` הוקצה לרשימת המנהלים; פעולות הניהול עצמן דורשות אימות דוא״ל לפני גישה. אין להרשות למשתמשים חדשים גישה לניהול בלי רשומה מפורשת ב־`tree_admins`.
- מחילים לפי הסדר את `db/001_schema.sql`, `db/002_private_admin_notes.sql` ואת `db/003_living_default.sql` על ענף ברירת המחדל בפרויקט החדש בלבד. הסקריפט הראשון יוצר בדיוק שני אנשים, ציפורה ומיכאל טטרואשוילי, ואת יחידת הנישואים שלהם. הוא אינו מניח אם הקשר נוכחי. שאר האנשים שהתווספו בהמשך נמצאים במסד בלבד ואינם נכללים בקובצי seed במאגר.
- כדי לקבוע סיסמה בפעם הראשונה, נכנסים ל־`/admin.html` ולוחצים „קביעת סיסמה”. לאחר הכניסה משלימים אימות דוא״ל בקוד חד פעמי. אין להכניס סיסמה לקוד הציבורי.
- מעתיקים את `.env.example` ל־`.env.local` וממלאים ערכים מן הפרויקט החדש בלבד. מריצים `npm install`, `npm run dev`. פרויקט Vercel `tetro-family-tree` מחובר למאגר החדש ונפרס אוטומטית מענף `main`. סביבת Production כוללת את `DATABASE_URL`, `NEON_AUTH_COOKIE_SECRET`, `AWS_ACCESS_KEY_ID` ו־`AWS_SECRET_ACCESS_KEY` כסודות, ואת `NEON_AUTH_BASE_URL`, `AWS_ENDPOINT_URL_S3`, `AWS_REGION` ו־`NEON_STORAGE_BUCKET` כהגדרות שרת. אין לשמור את ערכיהם במאגר.

## גבולות הגישה

`/api/tree` מחזיר רק אנשים גלויים וקשרים בין אנשים גלויים, עם `Cache-Control: no-store`. הערות `admin_note` נשמרות לניהול בלבד ואינן נשלחות ב־API הציבורי. העמוד אינו מחזיק snapshot ישן. `/api/admin` וכל כתיבה לתמונות דורשים session של Neon Auth וגם רשומה ב־`tree_admins` בצד השרת. החיבור למסד ופרטי S3 נשארים במשתני סביבה בשרת; bucket התמונות פרטי, ו־`/api/photo/:id` משרת תמונה רק כשהפרופיל גלוי. אין להפעיל Data API ציבורי על הטבלאות הללו. בהתקנה עם Data API יש להגדיר הרשאות RLS בהתאם, או להשאיר אותו כבוי.

המודל מקצה לכל ילד יחידת הורים אחת בלבד (אחד או שניים). שינוי הורה מתבצע בפעולת שיוך מחדש; בדיקות שרת מונעות הורות עצמית, מעגלים, כפילות פרופיל זהה וקשר ילד סותר. פעולת יצירת פרופיל והקישור הראשוני נמצאים באותה עסקת מסד. רשומות מוסתרות וקשריהן אינם יוצאים ל־API הציבורי. תאריך חלקי נשמר כמחרוזת בלי להשלים חודש או יום.

## שימוש בניהול

נכנסים ל־`/admin.html`, לוחצים „הוספת אדם”, ממלאים שם ובוחרים „ילד/ה של”. בוחרים את הזוג „ציפורה טטרואשוילי + מיכאל טטרואשוילי” בשדה הזוג, בודקים את סיכום הקשר, בוחרים אם להציג את האדם באתר ושומרים. אפשר להשאיר שם רוסי ותאריכים ריקים. תמונה אפשר להעלות אחרי שמירת הפרופיל. תיקון הורים נעשה באזור „קשרים ועריכה” בפרופיל הילד.

## בדיקת התקנה

נכנסים כמנהל, יוצרים אדם זמני וקשר עם זוג השורש, מרעננים את `/tree.html`, עורכים את הפרופיל ומצב היחידה, ובודקים העלאת תמונה והסתרה. מוחקים את פרופיל הבדיקה בכפתור „מחיקת פרופיל” ומוודאים שגם התמונה הוסרה. בדקו שה־API הציבורי אינו מחזיר אדם מוסתר, ושה־API המנהלי מחזיר 401 ללא session ו־403 לחשבון ללא הרשאה.

הפריסה הפעילה היא `https://tetro-family-tree.vercel.app/`. חשבון המנהל אומת. נבדקו בייצור יצירת פרופיל וקישור לזוג השורש, עריכה ורענון, שינוי מצב זוגיות, העלאת תמונה והסרתה כולל מחיקת הקובץ המאוחסן. כל רשומות וקובצי הבדיקה הוסרו. בעת כשל נתונים העמוד מציג הודעת אי־זמינות במקום מידע שמור שעלול להיות מיושן.

## עריכה מרוכזת

בניהול אפשר לעבור בין כמה אנשים, לערוך שדות וקשרים ולסקור את כל השינויים לפני „שמירת הכול”. השרת בודק גרסאות של פרופילים ויחידות משפחה, מאמת קשרי הורים ומבצע את השמירה בתוך עסקת PostgreSQL אחת. במקרה של סתירה אין שמירה חלקית. תמונות נשמרות בנפרד באמצעות API מוגן, לאחר שמירת טיוטת פרטים וקשרים.

מצב החיים הוא ברירת מחדל „בחיים” (`deceased=false`). המיגרציה השלישית מעדכנת רק רשומות שהיו ללא קביעה; סימון קיים של נפטר נשמר.
