# מערכת עצי המשפחה

מערכת משותפת לעצי משפחה פרטיים. התצוגה והניהול בעברית. כל אדם, קשר, הזמנה, הרשאת עריכה, רשומת יומן והתראה משויכים ל־`tree_id`, וכל API מאמת את העץ בצד השרת.

## התחלה

- פרויקט Neon הנפרד הוא `wispy-dream-84344395`, ענף הייצור `br-billowing-surf-b1tl8rri` באזור `aws-eu-central-1`. גבול נפח המסד המדווח בפרויקט הוא 512MiB.
- Managed Better Auth פעיל, וה־bucket הפרטי `tetro-photos` נוצר. חשבון המנהל `ilayspo@gmail.com` הוא הבעלים היחיד בטבלת `site_owner`. אין במוצר פעולה להוספת מנהל, ונתיבי ההרשמה וה־Admin API של Neon Auth חסומים בפרוקסי של האתר.
- בהתקנה חדשה מחילים לפי הסדר את `db/001_schema.sql` עד `db/007_multi_family_trees.sql`. המיגרציה השביעית משייכת את כל הנתונים הקיימים לטטרו ויוצרת מעטפת ריקה לפחמנוב, ללא אנשים או ראשי עץ מומצאים.
- כדי לקבוע סיסמה בפעם הראשונה, נכנסים ל־`/admin.html` ולוחצים „קביעת סיסמה”. לאחר הכניסה משלימים אימות דוא״ל בקוד חד פעמי. אין להכניס סיסמה לקוד הציבורי.
- מעתיקים את `.env.example` ל־`.env.local` וממלאים ערכים מן הפרויקט החדש בלבד. מריצים `npm install`, `npm run dev`. פרויקט Vercel `tetro-family-tree` מחובר למאגר החדש ונפרס אוטומטית מענף `main`. סביבת Production כוללת גם `RESEND_API_KEY`, `EMAIL_FROM` ו־`ADMIN_NOTIFICATION_EMAIL` לשליחת הזמנות ועדכונים. אין לשמור סודות במאגר.

## גבולות הגישה

`/tree.html`, `/api/tree` ותמונות הפרופיל דורשים קוד ייחודי ונפרד לכל עץ באורך 4–100 תווים. מסך הכניסה אינו חושף רשימת עצים; השרת מזהה את העץ לפי הקוד התקין בלבד. כל hash נשמר ב־`tree_settings`; הדפדפן מקבל cookie חתום, `HttpOnly`, שמכיל רק מזהי עצים וגרסאות גישה. החלפת קוד מבטלת את הגישה הקודמת לעץ הזה בלבד. `/api/tree` מחזיר רק אנשים וקשרים גלויים מהעץ שאושר. `/api/admin` דורש את חשבון הבעלים היחיד. `/api/profile` מאפשר לחשבון אחד להחזיק שיוך נפרד לעץ אחד או לכמה עצים, ולערוך רק את הפרופילים שהותרו באותו עץ. שינוי קשרים, הסתרה, מצב חיים והרשאות נשארים בניהול.

## הפרדה בין עצים

העץ נבחר ב־URL באמצעות slug, אך השרת פותר אותו לרשומת `trees` ומצליב הרשאה בכל קריאה. מזהה שמגיע מהדפדפן אינו מעניק גישה. קשרים כוללים `tree_id` ומוגנים גם במפתחות זרים מורכבים שמונעים חיבור אדם ויחידה מעצים שונים. תמונות חדשות נשמרות תחת `trees/{tree_id}/people/{person_id}/`; מפתחות התמונות הישנים של טטרו נשארים תקינים. הגדרות כותרת, פתיח, צבע, קוד צפייה וראשי עץ מנוהלות בנפרד לכל עץ.

נתיב `/api/auth/sign-up/email` ונתיבי `/api/auth/admin/*` מחזירים 404. חשבון אישי נוצר רק דרך `/api/profile/invite` עם token אקראי חד פעמי שפג אחרי שבעה ימים. במסד נשמר hash של ה־token. גם חשבון Neon Auth שנוצר מחוץ לזרימת ההזמנה אינו מקבל גישה לפרופיל או לניהול בלי שיוך פרטי בצד השרת.

המודל מקצה לכל ילד יחידת הורים אחת בלבד (אחד או שניים). שינוי הורה מתבצע בפעולת שיוך מחדש; בדיקות שרת מונעות הורות עצמית, מעגלים, כפילות פרופיל זהה וקשר ילד סותר. פעולת יצירת פרופיל והקישור הראשוני נמצאים באותה עסקת מסד. רשומות מוסתרות וקשריהן אינם יוצאים ל־API הציבורי. תאריך חלקי נשמר כמחרוזת בלי להשלים חודש או יום.

## שימוש בניהול

נכנסים ל־`/admin.html`, לוחצים „הוספת אדם”, ממלאים שם ובוחרים „ילד/ה של”. בוחרים את הזוג „ציפורה טטרואשוילי + מיכאל טטרואשוילי” בשדה הזוג, בודקים את סיכום הקשר, בוחרים אם להציג את האדם באתר ושומרים. תאריכים יכולים להישאר ריקים. תמונה אפשר להעלות אחרי שמירת הפרופיל. תיקון הורים נעשה באזור „מפת קשרים”.

בטאב „חשבון והרשאות” מזינים דוא״ל פרטי ושולחים הזמנה. אם האדם הוא ילד בעץ, מוצגים ההורים שהוגדרו עבורו ואפשר להעניק לכל אחד מהם הרשאת עריכה מפורשת. ההורה יראה את הילד ב־`/profile.html` לאחר הפעלת החשבון. שינויים אישיים מתפרסמים מיד, נכתבים ל־`profile_audit_log` ומתווספים ל־`notification_outbox`; כאשר Resend מוגדר, נשלח עדכון למנהל בזמן השמירה.

## בדיקת התקנה

נכנסים כמנהל, יוצרים אדם זמני וקשר עם זוג השורש, מרעננים את `/tree.html`, עורכים את הפרופיל ומצב היחידה, ובודקים העלאת תמונה והסתרה. מוחקים את פרופיל הבדיקה בכפתור „מחיקת פרופיל” ומוודאים שגם התמונה הוסרה. בדקו שה־API הציבורי אינו מחזיר אדם מוסתר, ושה־API המנהלי מחזיר 401 ללא session ו־403 לחשבון ללא הרשאה.

הפריסה הפעילה היא `https://tetro-family-tree.vercel.app/`. חשבון המנהל אומת. נבדקו בייצור יצירת פרופיל וקישור לזוג השורש, עריכה ורענון, שינוי מצב זוגיות, העלאת תמונה והסרתה כולל מחיקת הקובץ המאוחסן. כל רשומות וקובצי הבדיקה הוסרו. בעת כשל נתונים העמוד מציג הודעת אי־זמינות במקום מידע שמור שעלול להיות מיושן.

## עריכה מרוכזת

בניהול אפשר לעבור בין כמה אנשים, לערוך שדות וקשרים ולסקור את כל השינויים לפני „שמירת הכול”. השרת בודק גרסאות של פרופילים ויחידות משפחה, מאמת קשרי הורים ומבצע את השמירה בתוך עסקת PostgreSQL אחת. במקרה של סתירה אין שמירה חלקית. תמונות נשמרות בנפרד באמצעות API מוגן, לאחר שמירת טיוטת פרטים וקשרים.

מצב החיים הוא ברירת מחדל „בחיים” (`deceased=false`). המיגרציה השלישית מעדכנת רק רשומות שהיו ללא קביעה; סימון קיים של נפטר נשמר.

## תצוגה משפחתית לעומת הורות

`family_units.display_partner_id` הוא שדה תצוגה בלבד ליחידת הורה יחיד. הוא מאפשר להציג את בן/בת הזוג הנוכחיים בתוך אותו תא משפחתי, בעוד הילדים נשארים משויכים רק להורה האמיתי ב־`family_members`. השרת מאפשר לבחור רק אדם שכבר מקושר כבן/בת זוג של אותו הורה. כך למשל אפשר להציג את ארז ושרית כתא משפחתי עם ילדיו של ארז, בלי להגדיר את שרית כאמם ובלי להעניק לה הרשאות הורה.

## מין אופציונלי ושמות חוזרים

`gender` נשמר כ־`male`, `female` או `NULL` כאשר לא ידוע. בטופס ההוספה ובעריכה המרוכזת אפשר להשלים אותו מאוחר יותר. שני אנשים באותו שם ללא תאריך לידה ידוע יכולים להתקיים בענפים שונים; מניעת כפילויות לפי שם ותאריך חלה על תאריך לידה ידוע. בני המשפחה שהתווספו לאחר הקמת הפרויקט נמצאים ב־Neon ולא בקובצי seed ציבוריים.

האתר והממשקים פועלים בעברית בלבד. שכבת היישום אינה קוראת או מחזירה את עמודת השמות הישנה בשפה נוספת במסדים קיימים.
